# Auti AIgnosis — API Security Governance Rules (API_SECURITY_RULES.md)

> **CORE PRINCIPLE**  
> All HTTP/REST API endpoints must be architected under the assumption that external network traffic is potentially adversarial. Every request and response must be validated and sanitized.

---

## 1. Transport Security & Network Controls
1. **Compulsory TLS / HTTPS**:
   In production environments, all network communications must be encrypted using TLS 1.3 (or minimum TLS 1.2). Unencrypted HTTP traffic must be rejected or redirected immediately.
2. **CORS Configuration**:
   - Explicit origin allowlist loaded from `settings.CORS_ORIGINS`.
   - Wildcards (`"*"`) paired with `allow_credentials=True` are strictly forbidden in production configurations.
   - Allowed methods restricted to `["GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"]`.

---

## 2. Request & Response Validation (Pydantic v2)
1. **Schema Enforcement**:
   Every incoming JSON payload must be parsed through strict Pydantic models with explicit field types, length constraints, and regex patterns.
2. **Rejection of Unknown / Extra Keys**:
   Schemas must disallow unexpected properties to prevent parameter tampering and mass-assignment vulnerabilities.
3. **Response Model Filtering**:
   Every API endpoint returning sensitive data must declare an explicit `response_model`. Internal model fields (such as `hashed_password`, OTP secrets, internal system flags) must never be emitted into HTTP responses.

---

## 3. Rate Limiting & Denial-of-Service Defense
1. **OTP Endpoints**:
   - Maximum 1 OTP request per phone number per 60 seconds (`OTP_RESEND_COOLDOWN_SECONDS`).
   - Maximum 5 failed OTP verification attempts before token invalidation (`OTP_MAX_ATTEMPTS`).
2. **Authentication & Login**:
   - Strict rate limiting on `/api/auth/login` to prevent credential stuffing and brute force password attacks.
3. **Payload Size Boundaries**:
   HTTP request bodies are capped at a maximum of `1 MB` for JSON submissions to defend against memory exhaustion attacks.

---

## 4. Hardened Security Headers
All HTTP responses generated by the FastAPI gateway must include:
- `X-Content-Type-Options: nosniff` (prevents MIME sniffing)
- `X-Frame-Options: DENY` (clickjacking mitigation)
- `X-XSS-Protection: 1; mode=block` (legacy reflected XSS filter)
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Strict-Transport-Security: max-age=31536000; includeSubDomains` (HSTS enabled in production)
- `Content-Security-Policy: default-src 'self'`

---

## 5. Information Disclosure & Error Sanitization
1. **No Stack Traces**:
   Unhandled exceptions caught by the global exception handler must log technical tracebacks server-side, but return a generic response to the caller:
   ```json
   {
     "detail": "An internal server error occurred. Please try again or contact support."
   }
   ```
2. **No Database Error Leakage**:
   SQL errors (such as unique constraint failures or syntax exceptions) must be mapped to sanitized, client-safe error messages.
3. **No Internal Paths**:
   Model filesystem paths (e.g., `/app/ml/models/best_model.joblib`) must never be leaked to client responses.
